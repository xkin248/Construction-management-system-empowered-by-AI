# BuildSmart 手动验收测试清单

> 适用版本：GitHub Pages / Android APK / 本地 Flutter + backend。
> 目的：以真实用户角度验证每个主要功能、AI 推荐是否合理、以及数据、权限和错误处理是否可靠。
> 建议：每次只测试一个项目，并以 `QA-日期-功能` 作为新建项目、任务、文件名称的前缀，避免与正式资料混在一起。

## 开始前

- [ ] 使用**主管帐号**和**工人帐号**各登录一次；建议另准备第二名工人用于权限隔离测试。
- [ ] 准备 Project A、Project B；Project A 内至少有 General Worker、Skilled Worker、Foreman 及一名有 `Plumbing` specialty 的工人；Project B 也至少有一名工人。
- [ ] 为 Project A 准备：一个普通待办任务、一个已过期任务、一个清楚的 Plumbing / Electrical 任务、一个模糊任务（例如 `test`）。
- [ ] Android 真机或模拟器请开启相机和位置权限；要测试围栏失败时，把模拟 GPS 放在项目半径以外。
- [ ] 每一个失败都记录：案例编号、帐号角色、项目/任务 ID、设备/浏览器、网络状态、时间、预期结果、实际结果和截图/录屏。

### 缺陷优先级

- **P0（阻断）**：资料外泄、越权、数据丢失、无法登录、无法完成核心任务。
- **P1（严重）**：任务/审核/考勤/照片的业务结果错误。
- **P2（一般）**：错误提示、布局、排序、语言、效能问题。

| ID | 操作 | 正确结果 | 失败代表 |

## 1. 登录、会话、导航与基本 UI

- [ ] **A01 — 主管正确登入**：登入后进入主管 Dashboard，不出现工人专用的底部导航。
- [ ] **A02 — 工人正确登入**：登入后进入 Worker Home，只能看到自己的任务和资料。
- [ ] **A03 — 错误帐号/密码**：保留帐号与密码输入，显示可理解错误，不显示技术性 `DioException`。
- [ ] **A04 — 登入角色安全**：只切换 Worker/Supervisor 外观不能取得另一个角色的权限；后台按真实帐号角色判断。
- [ ] **A05 — 会话持久化**：网页刷新、App 强杀重开后仍维持登入；Logout 后刷新/重开必须回 Login。
- [ ] **A06 — 断网/服务冷启动**：出现 loading 或明确 Retry，绝不可显示假成功。Render 免费服务第一次唤醒可能较慢，但等待期间应有状态提示。
- [ ] **A07 — 总项目筛选器**：从 `All Projects` 切到 A、B，再切回 All；标题、列表、计数和资料必须同步。
- [ ] **A08 — 响应式画面**：在手机窄屏、桌面和浏览器缩放 125% 下，无被侧栏/底部栏遮住的按钮；输入时软键盘不挡住 Save/Submit。
- [ ] **A09 — 主题/语言**：切换 EN / 中文 / Malay 和浅色/深色后返回/重开，文字不截断，设定按预期保存。
- [ ] **A10 — 通知红点**：有未读通知时显示；读完/Mark all read 后数量和红点同步减少。

## 2. 项目与 GPS 围栏

- [ ] **P01 — 建立项目**：必填名称、地点、开始/结束日期、围栏半径正确校验；结束日不能早于开始日。
- [ ] **P02 — 当前位置**：按取得位置/重新定位时，地图中心跳至目前 GPS；储存后重开项目，纬经度与半径不应变回旧值。
- [ ] **P03 — 手动调整围栏**：点地图改变中心及拖动/修改半径后，画面和保存值一致。
- [ ] **P04 — 编辑项目**：修改名称、日期、位置或半径后，列表、详情和考勤逻辑全都更新。
- [ ] **P05 — 项目范围隔离**：A 的任务、工人、文件、考勤不应出现在 B；All Projects 才显示合并资料。
- [ ] **P06 — 项目状态**：无任务为 Planning；有未审核工作为 In progress；所有任务必须 **Approved/legacy Completed** 后才为 Completed，不能只是 Submitted 就完成。
- [ ] **P07 — 实际进度**：设两任务为 20% 和 80%，项目应约为 50%，不是只看「完成任务数量」。
- [ ] **P08 — 删除/归档**：对有任务/工人的项目操作时，应有明确确认或安全阻止；不可无声删除关联资料。

- [ ] **W01 — 新增工人**：姓名、电话、trade、skill level、项目正确储存；新增后能在该项目的任务表单中选择。
- [ ] **W02 — 编辑工人**：更改 trade、skill、specialty、项目后，刷新仍保留，AI 推荐同步采用新资料。
- [ ] **W03 — 搜寻与筛选**：以姓名、trade 搜寻，结果正确；切换 Project A/B 后不残留旧项目工人。
- [ ] **W04 — 100 人资料量**：载入、滚动、搜寻、桌面紧凑列表/卡片切换无明显卡顿、重复或漏人。
- [ ] **W05 — 项目转移**：把测试工人从 A 改到 B；他不应再出现在 A 的可派工名单。
- [ ] **W06 — 删除测试工人**：删除前有确认；删除后刷新不再出现；有历史任务时系统须安全处理而不是崩溃。
- [ ] **W07 — 权限隔离**：工人只能看到自身资料，不能经 URL、缓存或返回按钮看到其他工人的资料。

## 4. 任务建立、指派、筛选和审核闭环

- [ ] **T01 — 建立任务**：名称、说明、项目、trade、技能等级、人数、日期、优先级都储存正确。
- [ ] **T02 — 表单验证**：没有项目/技能等级/必要资料时给出具体提示；模糊标题如 `test` 不能导致乱派工。
- [ ] **T03 — 手动指派**：选择 1 名和多名工人后，主管卡片、任务详情、工人任务页一致。
- [ ] **T04 — 筛选**：Search、Priority、Pending、In progress、Awaiting Review、Completed、Overdue 结果正确；Approved 应在 Completed 逻辑中。
- [ ] **T05 — 全局项目范围**：在全局选 A 后，Tasks 只显示 A；切 B / All 不需要重启 App。
- [ ] **T06 — 工人开始工作**：工人把 Pending 改 In progress 后，主管刷新可看到状态和进度。
- [ ] **T07 — 进度更新**：1–99% 可储存、刷新后保留，并影响项目实际进度。
- [ ] **T08 — 提交完成证据**：工人不能在无照片下提交完成；只拍照、不填写文字说明也能提交。Cancel 不应提交。
- [ ] **T09 — Awaiting Review**：提交后任务显示 Awaiting Review / Pending review，而不是直接完成；主管收到待审核通知。
- [ ] **T10 — Approve**：主管批准后，任务为 Approved/Completed，审核日志有时间和操作者；项目进度/KPI更新。
- [ ] **T11 — Reject & rework**：必须填写理由；工人看到理由，只能补拍/重新提交；再次提交后重回 Awaiting Review。
- [ ] **T12 — Reopen**：Approved（或旧 Completed）任务只能按指定流程重新打开；重新打开后可继续工作且留下历史记录。
- [ ] **T13 — 任务资料/日志**：详情中项目、分配者、日期、优先级、照片和审核原因与实际一致。
- [ ] **T14 — 跨帐号隔离**：另一名未被分配的工人不能看、改、提交或下载该任务照片。

## 5. AI：先确认它实际做什么，再判定是否「智能」

### 真实情况（请用这个标准测试）

当前 `AI Auto-Assign` 的核心是**可解释的规则排序**：required skill level、trade/specialty、项目范围，必要时再使用 AI 服务/降级规则。它**并不会完整预测**工人的距离、工作量、未来排程或真实生产效率。Worker task board 的部分「AI 指示」目前也可能是模板化内容。

所以，正确行为不是「一定像 ChatGPT 一样聪明」，而是：**不乱猜、不给不合资格的人自动派工、清楚显示降级/规则结果、让主管最终确认。**

- [ ] **AI01 — 未选技能等级**：点 AI Auto-Assign 时，提示先选 Required Skill Level，不应发送空建议或直接派人。
- [ ] **AI02 — 同项目技能排序**：在 A 有 General / Skilled / Foreman 时，为 Skilled 工作建立任务；Skilled 应优先，General 绝不可被自动确认指派。
- [ ] **AI03 — specialty 匹配**：Plumbing 任务必须优先/只自动选有 Plumbing specialty 的合格工人；Electrical/其他项目的人不能被自动派上。
- [ ] **AI04 — 项目限制开关**：开启 `Only match workers in this project` 时绝不可跨项目；关闭时才允许显示全局候选。
- [ ] **AI05 — 模糊任务保护**：如 `test`、`help`、无 trade 的任务，应提示资料不足/不派人；不应随机选第一个工人。
- [ ] **AI06 — 建议非自动提交**：按 AI Auto-Assign 后先显示建议；只有按 Create/Save Task 才真正写入分配，且主管可移除或替换候选。
- [ ] **AI07 — 人数与重复**：Workers Needed 为 N 时，不多派、不重复；刷新任务后分配仍与确认名单相同。
- [ ] **AI08 — 纠正错误**：故意把 Plumbing 任务手动错派给非 Plumbing 工人，再做 Auto-Assign；系统应修正或明确提示，不能静默保留错误分配。
- [ ] **AI09 — 已审核任务保护**：Approved 任务执行 Auto-Assign 后，人员、状态、审核资料绝不可被改动。
- [ ] **AI10 — AI 状态透明**：Gemini/service 不可用时，画面应写明 Rule-only / degraded / unavailable（或等价说明），不能假称模型在线或给出虚构信心分数。
- [ ] **AI11 — 进度预测**：选择 A 后点 Update，显示属于 A 的 current progress、风险、建议、日期/信心；换到 B 后旧 A 数据不能残留。
- [ ] **AI12 — 预测已审核任务**：批准完成后再预测，模型/规则必须把 Approved 视为完成。
- [ ] **AI13 — worker task board**：工人只看自己的任务、说明、优先级和截止日；Approved 不应继续计入未完成/过期提醒。
- [ ] **AI14 — AI 权限**：工人不能批量 auto-assign、查看主管 AI decision log、改变他人任务。

> **将以下归类为「AI/产品改善」而非必然程序错誤：**缺少工作量、距离、未来排程、工人偏好和实际效率的排序因素；这些不是当前规则引擎承诺的输入。若你需要真正智能派工，记录为功能需求并收集可用资料来源。

## 6. 考勤、GPS、相机与 Firebase 相关流程

- [ ] **G01 — 围栏内 Check-in**：GPS 在项目半径内，相机自拍成功后，显示正确时间/Present，主管 Attendance Today 能看到该工人。
- [ ] **G02 — 围栏外拒绝**：GPS 在半径外应有清楚「outside geofence」提示，且不能产生 Present 记录。
- [ ] **G03 — 权限拒绝**：拒绝 Location / Camera、关闭 GPS、取消拍照，各情况均不崩溃、不误记考勤，并有可执行的恢复提示。
- [ ] **G04 — 重复 Check-in**：同日重复打卡应被合理处理（提示已打卡或更新按明确规则），不可产生无解释的重复纪录。
- [ ] **G05 — Check-out**：围栏内 checkout 后时间、状态、自拍（若要求）正确；围栏外失败时原本考勤仍存在。
- [ ] **G06 — 心跳/刷新**：GPS/考勤刷新不会意外反复创建记录或不断跳动时间。
- [ ] **G07 — 主管范围**：选 A/B 后 Attendance 列表、人数、图表都随范围更新；画面标题不可仍错误写 `All projects`。
- [ ] **G08 — 隐私/权限**：登出、无痕或另一工人帐号不能读取其他人的位置、自拍、考勤详情。

## 7. 文件、进度照片与下载

- [ ] **F01 — 上传图片**：在 Project A 上传 JPG/PNG，进度条从 0% 到完成，成功后立即出现在 A。
- [ ] **F02 — 上传文件**：上传小型 PDF/DOCX，名称、类别、大小、上传者和时间正确。
- [ ] **F03 — 预览**：图片/PDF Preview 可以打开正确的文件，而不是空白页或其他项目文件。
- [ ] **F04 — 下载**：Download 后档名、档案大小、内容和原档一致；重新打开仍可读取。
- [ ] **F05 — 项目隔离**：A 的文件不会在 B 显示；B 的帐号/工人不能从旧 URL 或浏览器缓存读取 A 的私密文件。
- [ ] **F06 — 删除**：删除测试文件需要确认；刷新后不再显示，也不会误删同名其他文件。
- [ ] **F07 — 完成照片**：流程同 T08–T10，且主管与获指派工人都可见；不可公开给未授权帐号。
- [ ] **F08 — 网络中断**：上传途中断网应报失败而非显示完成；恢复网络后可重新上传。当前版本**没有保证本机离线照片/GPS自动待同步队列**，不可把「自动补传」当作预期行为。

## 8. 报告、问题、通知、日常工作与工具

- [ ] **O01 — Daily Report**：选择项目、天气、人数、今日进度、材料、问题后提交；Recent Reports 显示新纪录且资料完整。
- [ ] **O02 — 重复日报**：同项目同一天重复提交时，系统按既定规则明确拒绝或更新；不可静默产生不明重复。
- [ ] **O03 — 报告问题**：建立不同 severity/category 的 issue，Active Issues 出现；Resolve 后状态/列表/通知同步。
- [ ] **O04 — 任务通知**：指派任务后工人收到通知；点通知可打开正确任务；提交证据后主管收到审核通知。
- [ ] **O05 — 已读状态**：打开通知或 Mark all read 后重开 App/网页仍保持已读。
- [ ] **O06 — 通知偏好**：切换通知 setting、重开设定，偏好保持；关闭一个类别不应影响无关类别。
- [ ] **O07 — Daily safety/common task**：完成、拍照、取消、重复提交的资料和状态正确，不会提交空照片。
- [ ] **O08 — Toolbox take/return**：借用、归还、确认/取消、刷新后库存/记录一致；不能重复归还或把同一工具借给多名人。

## 9. 安全、可靠性与性能

- [ ] **S01 — 角色权限**：worker 访问主管 URL、返回历史、Deep link 或 API 后，必须被拒绝/导回正确页；不能建立项目、删除文件、审核任务或指派其他人。
- [ ] **S02 — 项目权限**：Project B 的工人不能读改 A 的任务、照片、文件、考勤、日报、issue。
- [ ] **S03 — 刷新持久性**：建立/编辑/审核/上传后，浏览器刷新和 App 重开均保留服务器真相。
- [ ] **S04 — 并发操作**：主管审核时工人同时刷新/重试，不会出现双重审核、重复照片、跳回旧状态或 500。
- [ ] **S05 — 规模**：100 workers、4–5 projects、每项目约 10 tasks 下，Dashboard/Tasks/Workers/Files 在合理时间可操作，不白屏、不无限 loading。
- [ ] **S06 — 错误文字**：断网、401/403、404、500 时显示用户可理解的说明与 Retry，避免只显示 `DioException`。
- [ ] **S07 — 资料不丢失**：取消表单/拍照/审核对话框不会意外写入；页面返回后未提交内容按产品设计保留或明确提示会丢失。
- [ ] **S08 — 可访问性**：大字体、横屏、键盘导航、屏幕阅读器下关键按钮仍可见、可点和有意义标签。

## 验收建议

可以把所有 **R、T、G、F、S01–S04** 视为上线门槛：任何 P0 或 P1 未通过，先不要把版本交给真实现场使用。UI 排版和 AI 改善需求可记录为 P2/产品迭代，但权限、照片证据、GPS 围栏和审核状态必须先正确。
