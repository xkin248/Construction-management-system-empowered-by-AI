## 1. 系统概览

BuildSmart 是一个现代化的建设工程管理系统，采用前后端分离架构，基于 FastAPI（Python）和 Flutter 技术栈构建。

### 技术架构
- **后端**: FastAPI + SQLAlchemy + SQLite / PostgreSQL
- **前端**: Flutter (支持 Android/iOS/Web)
- **数据库**: SQLite（本地）/ PostgreSQL（生产，`DATABASE_URL`）
- **地理位置**: GPS 地理围栏 + Haversine 公式
- **AI**: scikit-learn 语义匹配 + Gemini `gemini-1.5-flash`
- **实时通信**: WebSocket + FCM 推送

### 2.4 GPS 地理围栏考勤 (Attendance)

#### 核心功能
- 工人进场打卡 (GPS 验证)
- 工人退场打卡
- 心跳位置上报
- 自动离场检测与取消打卡
- 今日考勤汇总统计
- 迟到/早退标记

#### 地理围栏逻辑
- 使用 Haversine 公式计算两点间距离
- 进场验证：必须在地理围栏内
- 离场验证：记录最终距离
- 自动取消：连续2次越界心跳后自动取消打卡状态

#### API 接口
- `POST /api/attendance/check-in` - 进场打卡
- `POST /api/attendance/checkin` - 兼容版进场打卡
- `POST /api/attendance/heartbeat` - 心跳上报
- `POST /api/attendance/check-out` - 退场打卡
- `POST /api/attendance/checkout` - 兼容版退场打卡
- `GET /api/attendance/worker/{wid}/today` - 获取工人今日考勤
- `GET /api/attendance/today` - 获取今日考勤汇总

#### 数据模型
```sql
attendance_logs:
  - attendance_id (主键)
  - worker_id (外键)
  - project_id (外键)
  - check_in_time
  - check_out_time
  - in_lat (进场纬度)
  - in_lng (进场经度)
  - out_lat (退场纬度)
  - out_lng (退场经度)
  - in_distance_m (进场距离中心，单位：米)
  - out_distance_m (退场距离中心，单位：米)
  - status (checked_in/checked_out/left_early/absent/rejected)
  - last_heartbeat_time
  - last_heartbeat_lat
  - last_heartbeat_lng
  - out_of_fence_count (连续越界次数)
```

### 2.12 AI 辅助能力 (AI)

#### 核心功能
- **语义工人匹配**：scikit-learn 离线模型（joblib 持久化），按工种与任务描述计算候选工人；模型产物缺失或版本偏移时降级为关键词规则，并在启动日志与 `/health` 中显式暴露状态
- **外部大模型**：`google-generativeai`，默认模型 `gemini-1.5-flash`（可用 `GEMINI_MODEL` 覆盖），用于任务分析与决策建议；未配置 API Key 时自动降级，不影响主流程
- **决策审计**：每次 AI 决策写入 `ai_decision_log`（输入摘要、输出、置信度、耗时、阶段），支持按项目与阶段统计

#### API 接口
- `POST /api/ai/tasks/analyze` - 任务分析
- `POST /api/ai/tasks/auto-assign` - 自动派工
- `GET /api/ai/projects/{pid}/progress-prediction` - 工地进度预测
- `GET /api/ai/projects/{pid}/prediction-history` - 预测历史
- `GET /api/ai/decision-log/stats` - AI 决策统计

### 2.13 通知中心 (Notifications)

#### 核心功能
- 双收件箱：监理 `notifications`、工人 `worker_notifications`，各自带未读计数与全部已读
- 触发点（业务侧写入，写入即推送）：
  - 任务分配（含 AI 自动派工）
  - 问题上报（监理）
  - 安全事件（监理 + 自动指派给最近的安全员）
  - 考勤异常（围栏外打卡被拒、连续越界自动签退）
  - 任务超期（后台扫描，每天每任务最多一次）
  - 日报提醒（需在设置中开启 `notif_daily_report`）
- 分类开关：考勤 / 任务超期 / 任务分配 / 问题 / 安全 / 日报 / 邮件 / 推送，每类独立开关，关闭即不落库
- 实时通道：`WebSocket /api/ws/notifications`，通知落库后即时推给在线监理
- 离线通道：FCM（`firebase-admin`），设备 token 通过接口注册；未配置凭据或推送失败时静默降级，不影响应用内通知
- 后台扫描器：默认每 30 分钟扫描一次超期任务与当日未提交的日报；`ENABLE_NOTIFY_SCHEDULER=0` 可关闭，`NOTIFY_SWEEP_INTERVAL_SECONDS` 可调整周期

#### API 接口
- `GET /api/notifications` - 监理通知列表
- `GET /api/notifications/unread-count` - 未读计数
- `GET /api/notifications/{notification_id}` - 通知详情
- `PUT /api/notifications/{notification_id}/read` - 标记单条已读
- `PUT /api/notifications/read-all` - 全部已读
- `GET /api/notifications/settings`、`PUT /api/notifications/settings` - 通知开关
- `GET /api/notifications/worker/{worker_id}` - 工人通知列表
- `GET /api/notifications/worker/{worker_id}/unread-count` - 工人未读计数
- `PUT /api/notifications/worker/{worker_id}/read-all` - 工人全部已读
- `POST /api/notifications/register-token` - 注册 FCM 设备 token
- `WS /api/ws/notifications?token=...` - 实时推送

### 3.1 前端易用性改造（新手友好）

> 目标：让第一次使用系统的工地用户在首屏就能判断"我现在该做什么"，减少术语与信息密度带来的理解成本。

**导航层**
| 角色 | 导航结构 |
|------|----------|
| 主管端 | 底部固定 5 项：Dashboard / Projects / Tasks / Workers / More；Files、Attendance、Notifications、Profile 收敛进「更多工具」底部弹层，每项带一句用途说明 |
| 主管端（宽屏） | 侧栏按「核心功能 / 更多工具」两组归类，从 More 进入子页时对应 tab 保持高亮 |
| 工人端 | 底部固定 5 项：首页 / 任务 / 考勤 / 提醒 / 个人资料（改造前无独立任务入口） |

**首屏减负**
| 页面 | 首屏保留 | 下沉内容 |
|------|----------|----------|
| 主管 Dashboard | 欢迎区、3 张核心 KPI（在岗人数 / 进行中任务 / 生产率）、3 个快捷操作、主管一键打卡 | 周考勤图、任务分布、项目产能、即将到期项目、未解决问题收进「更多洞察」折叠区；AI 进度预测默认收起，点「更新」才调用接口 |
| 工人 Dashboard | 欢迎卡、3 张 KPI、「今天要做的三件事」（今日任务 / 打卡 / 异常上报） | 考勤明细与任务看板收进折叠区 |

**空态与异常态**
- 通用组件 `GuidedEmptyState` / `FilteredEmptyState`：图标 + 标题 + 一句说明 + 主操作按钮，覆盖 Projects / Tasks / Workers / Files / 通知 / 工人任务列表
- 筛选或搜索无结果时，与"确实没有数据"区分，给出「清空筛选」动作
- 加载态：`SkeletonDashboard` / `SkeletonList` / `SkeletonCardGrid` / `SkeletonDetail` / `SkeletonSection` 骨架屏，首屏不再以全屏转圈作为唯一加载提示
- 失败态：`FailureState` / `FailureInline` 按 `offline / timeout / server / unknown` 四类给出原因与「重试」按钮；Dashboard 局部失败保留页面其余内容并顶部提示

**性能与可维护性**
- 长列表统一改为 `ListView.builder` / `CustomScrollView + SliverList` 懒构建，滚动条常驻，下拉刷新保留
- 列表项抽离为独立组件：`ProjectCard`、`WorkerListCard`、`NotificationListTile`、`FileGridCard` / `FileListTile`、`WorkerTaskTile`
- 图片组件 `SignedFileImage` 支持 `cacheWidth` / `cacheHeight`，限制解码尺寸

**可访问性**
- `lib/widgets/a11y.dart` 提供语义封装：导航项、卡片点击区、状态徽标、图标按钮均有语义标签或 tooltip
- `lib/theme/text_scale.dart` 统一限制最大文字缩放 1.3 倍，避免系统字号放大后密集卡片截断

**多语言与日志**
- 新增文案全部同步 en / ms / zh 三语，缺译回退英文
- 调试输出收敛为 `debugPrint` 并加 `kDebugMode` 判断，release 不输出；请求日志不再打印 token 与请求体

- 通过 `/html` 路径访问

## 5. 核心算法与逻辑

### 5.1 GPS 距离计算 (Haversine Formula)
```python
def distance_m(lat1, lng1, lat2, lng2):
    EARTH_RADIUS_M = 6371000.0
    p1 = math.radians(lat1)
    p2 = math.radians(lat2)
    dphi = math.radians(lat2 - lat1)
    dlambda = math.radians(lng2 - lng1)
    a = sin(dphi/2)^2 + cos(p1)*cos(p2)*sin(dlambda/2)^2
    return 2 * EARTH_RADIUS_M * asin(sqrt(a))
```

## 7. 系统限制与边界

### 当前限制
1. **数据库**：本地开发用 SQLite，生产通过 `DATABASE_URL` 连接 PostgreSQL（`psycopg2`），云部署同为 PostgreSQL
2. **认证**：仅 `worker` / `site_supervisor` 两类账号，JWT 鉴权，按角色做粗粒度接口隔离（worker 调用监理接口、或反向调用，均返回 403）；无独立管理员后台，无字段级细粒度权限
3. **存储**：支持附件上传与下载（`uploads/` 落盘 + 元数据入库 + 临时下载链接），未接入云对象存储；单机磁盘容量即上限，多实例部署需共享存储
4. **AI**：已接入两层能力——本地 scikit-learn 语义匹配模型 + Gemini `gemini-1.5-flash`（`google-generativeai`）；未配置 Gemini API Key 时自动降级为规则算法，模型状态在启动日志与 `/health` 中可见
5. **通知**：应用内通知（监理 + 工人双收件箱）、WebSocket 实时推送、FCM 离线推送、后台定时扫描（任务超期 / 日报提醒）均已接通；FCM 需自行配置 `firebase-admin` 凭据与设备 token，未配置时降级为仅应用内通知
6. **报表**：提供 KPI 汇总接口与进度预测，未集成图表库，前端以卡片与列表展示
7. **预算**：无预算与成本管理功能
8. **材料**：无材料与设备管理功能
9. **审批流**：无多级审批工作流；任务状态变更与重开为单角色操作并留有审计日志

### 说明
第 7 类（预算）与第 8 类（材料设备）为未开发模块，本说明书不声明其能力。其余模块均为已实现、可运行状态，测试覆盖见 `docs/测试报告.md`。
