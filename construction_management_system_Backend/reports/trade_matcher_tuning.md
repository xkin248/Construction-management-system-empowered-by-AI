# Trade matcher – tuning result on dev and on a fresh test split

Generated by `scripts/eval_trade_test.py` (LLM fallback disabled, deterministic).

**What is being measured.** The keyword + centroid matcher only: `ai._TRADE_CLASSIFIER` is pinned to `False` for every run here, so the supervised classifier layer (`data/trade_classifier.joblib`, sha256 `f12ab8d0abb82afa6b8cea777a836218971bf8cc23ceaff61365136d2222d2cf`) never scores a row. That artefact is trained on all labelled rows, so scoring with it would measure memorisation, not keywords. Classifier numbers live in `reports/trade_matcher_validation.md`.

## 1. Split protocol

* Dataset (518 labelled rows from `job_categorization.parquet`, 67 mapped categories).
* Group split by cleaned title so identical wording never straddles splits.
* **dev** = 104 rows, seed 42, 20 % — the previously reported holdout. Its failures were the *only* input used to design the keyword changes.
* **test** = 83 rows, seed 2026, 20 % of the remaining pool — carved out of the old training pool, excluded from training and never inspected while tuning. It is scored once, as-is.
* dev rows are scored by a model trained on 414 rows; test rows by a model trained on 331 rows (test rows removed). No row is ever scored by a model that saw it.

## 7. Boundary cases (ambiguity documented, not forced)

| task text | dataset label | also defensible | why it is left as a boundary |
| --- | --- | --- | --- |
| `scaffold` | laborer | carpenter | Erecting/dismantling scaffolding is generic site labour, but a scaffold carpenter legitimately owns the same wording. |
| `post tensioning ironworker` | masonry (Reinforcing Iron and Rebar Workers) | welding (Structural Iron and Steel Workers) | Post-tensioning strand work sits with rebar/reinforcement, while a structural ironworker welds. Both readings exist on site, so the ambiguous bare word `ironworker` was only removed from the hard rule layer, not rewritten case by case. |
| `sewage screen operator` | plumbing (Septic Tank Servicers and Sewer Pipe Cleaners) | equipment (plant operator) | A screen operator runs mechanical screening at a treatment plant; the `operator` reading is defensible. Fixed only through `sewage`/`septic` vocabulary, not by special-casing. |
| `radiological control and safety technician` | insulation (Hazardous Materials Removal Workers) | supervision (safety/inspection) | Hazmat removal and radiological safety overlap; the safety-inspection reading is legitimate. |
| `van loader` | laborer (Laborers and Material Movers) | equipment (Loading Machine Operators) | Manual loading vs machine loading. Vocabulary was extended with `loader`/`mover`, but a `wheel loader operator` task is still resolved to equipment. |
| `truck washer` | laborer (Cleaners of Vehicles and Equipment) | equipment (heavy truck driver/operator trade) | Vehicle cleaning is labour, yet the word `truck` pulls towards the operator trade; both readings survive in production wording. |
| `auto detailer` | laborer (Cleaners of Vehicles) | painting / glazing | Detailing involves coating and glass care, but the occupation is vehicle cleaning. |
| `pottery kiln builder` | masonry | carpenter | Kiln construction is refractory/masonry work, though kiln furniture and casing are carpentry. |
| `boiler engineer` | hvac (Stationary Engineers and Boiler Operators) | welding (Boilermakers) | Boiler operation is hvac in the dataset; boiler making/fabrication is welding. Distinguished by adding boiler/stoker/furnace vocabulary on the hvac side. |

## 8. Residual errors on test — and why they were left alone

These patterns are visible in the test failures above. Fixing them now would mean tuning against the test set, which destroys its value as an estimate, so they are handed to the next tuning round unchanged. The next round needs a **third** untouched split (e.g. seed 31337) to validate any fix.

| pattern | rows | cause | candidate fix |
| --- | ---: | --- | --- |
| `ornamental plasterer`, `plasterer apprentice`, `molding plasterer` → masonry | 3 | the dataset files *Plasterers and Stucco Masons* under **drywall**, but `plaster` / `stucco` are still owned by the masonry rule layer | move `plaster`-family vocabulary to drywall and keep `stucco` only with an explicit stucco cue |
| `precast concrete ironworker` → masonry (was welding) | 1 | removing the bare `ironworker` cue to fix masonry cost this row to the new `reinforc` / `precast` cues | add a `structural iron` compound cue on the welding side |
| `soldering / brazing machine operator` → equipment | 2 | `operator` dominates the equipment rule layer even when the head noun is a joining process | require a machine/plant noun for `operator` |
| `material handler`, `shipping and receiving material handler` → insulation | 2 | hazmat vocabulary (`hazardous`) raised insulation similarity for generic *materials* phrasing | gate the hazmat cues behind `asbestos` / `radiological` / `removal` |
| `ceramic painter` → tiling | 1 | `ceramic` is a tiling cue, `painter` a painting cue; the rule layer lets the noun win | arbitrate by suffix (`*er` = occupation) |
| painting 25 %, drywall 20 % on test | 9 | these rows are only separable from the job title with occupational context the 518-row subset does not contain | needs more labelled rows, not more keywords |
